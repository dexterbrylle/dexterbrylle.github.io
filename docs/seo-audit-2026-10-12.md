# SEO audit, 12 October 2026

Audited https://dexterbrylle.com and the Astro source. This is a personal engineering site and notebook. The working SEO focus is Dexter Brylle Matos, site reliability engineering, software, systems, and security, based on the published profile. No Search Console or analytics data was available.

## Assessment

The site has a sound foundation: HTTPS, an HTTP-to-HTTPS 301 redirect, unique canonical URLs, English language metadata, server-rendered content, and existing WebSite, Person, WebPage, and Article structured data. JSON-LD was inspected in the live browser, rather than inferred from a text fetch. Important pages are linked directly from navigation, and notes are linked from the home page and notes index.

The largest verified technical problem was broken sitemap discovery. The remaining opportunity is substantive writing that demonstrates firsthand engineering experience. No claim about actual Google index coverage, rankings, traffic, backlinks, or field Core Web Vitals can be made from this audit.

## Findings and applied fixes

| Finding | Evidence | Impact / priority | Applied fix |
| --- | --- | --- | --- |
| robots.txt advertises a missing sitemap | Live robots.txt referenced `/sitemap.xml`; that URL returned HTTP 404. `/sitemap-index.xml` returned valid XML referencing `/sitemap-0.xml`. | High / 1 | Updated robots.txt to advertise the generated sitemap index. |
| Empty pages are indexable and included in the sitemap | Certifications has no entries; Homelab has no services and disconnected telemetry. Both live pages had `index, follow` and appeared in the sitemap. | Medium / 2 | Added conditional `noindex, follow` and matching sitemap exclusions. Both become indexable automatically once their inventories have entries. Pages remain available through navigation. |
| Profile and Notes search metadata is vague | Live titles were `Profile | Dexter Brylle` and `Notes | Dexter Brylle`; descriptions were generic and did not explain the profile's specialization or the writing's coverage. | Medium / 2 | Added descriptive titles and descriptions based on existing content. |
| Articles lack a visible author profile link | Article markup supplied an author in JSON-LD but the entry header only showed date, tags, title, and description. | Low / 3 | Added a visible author byline linking to `/about/`, with the published job title. |

Descriptions are written for accuracy and usefulness. Character counts are not treated as a Google ranking rule or guaranteed display width. Google may generate different snippets and titles.

## Remaining technical findings

| Finding | Evidence | Impact / priority | Next action |
| --- | --- | --- | --- |
| The www hostname does not resolve from the audit environment | An external `curl -IL https://www.dexterbrylle.com` failed DNS resolution. The apex hostname served HTTP 200. | Medium / 2 | Configure www DNS and HTTPS at the domain provider, then permanently redirect it to the apex hostname while preserving paths and queries. This requires DNS/hosting access. |
| Index coverage is unknown | A public `site:dexterbrylle.com` search returned no results. This search is not a reliable inventory of Google indexing. | Unknown / 2 | Verify the domain in Search Console, submit `/sitemap-index.xml`, and inspect the homepage, profile, and notes URLs. Check indexing exclusions and selected canonicals. |
| Field performance is unverified | One live desktop navigation had approximately 339 ms TTFB and 1.04 s DOMContentLoaded. These are single navigation timings, not Core Web Vitals. | Unknown / 3 | Check PageSpeed Insights and Search Console for LCP, INP, and CLS on real traffic. Do not infer a passing field score from local browser checks. |

The `/blog/` legacy pages already use immediate meta refresh, destination canonicals, and noindex, and are excluded from the sitemap. Server redirects would provide explicit permanent HTTP status codes but require configuration outside the static GitHub Pages artifact. No redirect failure was observed in local checks.
